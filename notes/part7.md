## File 28: `src/pages/AIAssistantPage.jsx`

### Basic Information
* **File location:** `src/pages/AIAssistantPage.jsx`
* **Why this file exists:** A dedicated ChatGPT-like interface injected with real-time campus data. Students can ask about upcoming events, hackathon ideas, or find teammates using natural language.

### Internal Mechanics (RAG Architecture)
This file implements a lightweight **RAG (Retrieval-Augmented Generation)** pattern. 
1. **Pre-fetching Context:** As soon as the page loads, `useEffect` triggers a `Promise.all` fetch to Supabase. It pulls *every active event* and *every available student profile*.
2. **Context Injection:** When the user types a question (e.g., "Who can help me with React?"), the `askAssistant` function doesn't just send the question to Gemini. It passes the question *and* the entire fetched database context to the `answerQuestion` function (from `campusAssistant.js`).
3. **Smart Formatting:** The `formatMessage` helper function parses the AI's markdown response, converting bullet points (`- `) into styled HTML elements without needing a heavy markdown-parsing library.

### Interview Section for `AIAssistantPage.jsx`
* **Hard Question:** Passing the entire student database to the LLM context is fine for 50 users, but what happens when you have 5,000 students? Won't you hit token limits?
  * *Ideal Answer:* Yes, the current architecture is an MVP approach. For a production scale, I would transition from passing the raw JSON array to implementing a **Vector Database**. I would generate embeddings for student skills and event descriptions, store them in Supabase using `pgvector`, and then perform a similarity search to only pass the top 5 most relevant records to the LLM prompt.

## File 30: `src/pages/ChatPage.jsx`

### Basic Information
* **File location:** `src/pages/ChatPage.jsx`
* **Why this file exists:** The central communication hub. It handles 1-on-1 direct messages and group chats (like the ones generated by the AI Team Builder).

### Internal Mechanics (WebSockets & Real-Time)
This is arguably the most technically complex React component in the app (900+ lines).
1. **Two-Tier Subscription System:** It uses Supabase Realtime (WebSockets) via `.channel()`. 
   - It subscribes to the `conversations` table to instantly update the sidebar when someone's name changes or a new chat is created.
   - It subscribes to the `messages` table specifically filtered by `conversation_id=eq.${activeConv.id}` to instantly append new messages to the chat window.
2. **Debounced Global Search:** When searching for a new user to chat with, it uses a `setTimeout` (debounce) of 300ms. This prevents the app from spamming the Supabase database with a query for every single keystroke.
3. **Unread Badges:** When a user clicks a conversation, it immediately triggers an `update` to the `conversation_participants` table to set `unread_count = 0`, instantly clearing the notification badge.

### Interview Section for `ChatPage.jsx`
* **Senior Question:** How do you handle React state updates when a WebSocket message arrives? Why is it tricky?
  * *Ideal Answer:* WebSockets execute outside of React's normal render cycle. If I just used `setMessages([...messages, newMsg])`, it would use a stale closure (an outdated version of the messages array). Instead, I must use the functional update pattern: `setMessages((prev) => [...prev, newMsg])` to guarantee I am appending to the most recent state.

# 12. Dynamic Routing & Directory Systems

## File 34 & 35: `src/pages/EventDetailPage.jsx` & `src/pages/ClubDetailPage.jsx`

### Basic Information
* **Why they exist:** These are the dynamic routes (`/event/:id` and `/club/:id`) that display the full details of a specific event or club.

### Internal Mechanics
* **Dynamic Fetching:** Both rely heavily on `useParams()` from `react-router-dom` to grab the ID from the URL, which is then used in a `useEffect` to query Supabase.
* **Complex Data Aggregation (`EventDetailPage`):** This file doesn't just fetch the event. In a single load, it checks:
  1. The total number of registrations (`event_registrations(count)`).
  2. Whether the *currently logged-in user* is already registered.
  3. Whether the user has bookmarked the event.
* **Dynamic Form State (`EventDetailPage`):** It handles both Solo and Team registrations via a single modal. If `isTeamEvent` is true, the `registrationForm` state dynamically expands to include a `teamName`, `captainContact`, and an array of `members` (up to `max_team_members`), validating that all required fields are filled before submitting.
* **Fuzzy Matching (`ClubDetailPage`):** Because events don't strictly have a foreign key to the `clubs` table (they rely on `club` string or `organizer_id`), this page fetches all events and performs a client-side filter using a `normalize` function to fuzzy-match events to the club profile.

### Interview Section
* **Question:** In `EventDetailPage`, why is the total registration count fetched using a relational query (`event_registrations(count)`) instead of doing a `.select('*')` and counting the array in JavaScript?
  * *Ideal Answer:* Performance and bandwidth. Doing a `.select('*')` on a massive event would download thousands of rows of data just to count them. Using Supabase's aggregate count feature pushes the calculation to the PostgreSQL database, returning only a single integer over the network.

## File 38 & 39: `src/pages/ForgotPasswordPage.jsx` & `src/pages/ResetPasswordPage.jsx`

### Basic Information
* **Why they exist:** To handle the Supabase password recovery lifecycle.

### Internal Mechanics
* **Lifecycle:** 
  1. User submits email in `ForgotPasswordPage.jsx`.
  2. Code calls `supabase.auth.resetPasswordForEmail()`, passing a `redirectTo` URL.
  3. User clicks the link in their email, which redirects them to `/reset-password` on the frontend.
  4. The `ResetPasswordPage.jsx` loads and uses `supabase.auth.getSession()` in a `useEffect` to verify the user actually arrived via a secure email link.
  5. The user submits a new password, triggering `supabase.auth.updateUser({ password: newPassword })`.
* **Security:** If `getSession()` returns null on the reset page, it means a user just typed `/reset-password` directly into their browser without clicking an email link. The UI immediately throws an error state to prevent them from attempting to change a password.
